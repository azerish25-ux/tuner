# Genuine Watch face capture: remaining manual step

The automated job captures two actual app pages, not a system face. `complication_face.status` stays `manual_remaining`; it is never counted among those images.

Apple requires Watch screenshots, with a consistent Watch pixel size across localizations, and permits 1–10 screenshots per device size. It does not specify a separate complication-face screenshot as a minimum submission requirement. The third frame requested by this project's release checklist remains a creative/verification item. [Screenshot specifications](https://developer.apple.com/help/app-store-connect/reference/app-information/screenshot-specifications), [Watch app information](https://developer.apple.com/help/app-store-connect/create-an-app-record/add-watchos-app-information/).

For a genuine face image, install the built app and widget extension on the same paired 416×496 simulator. Open Today with a current snapshot; then use the Digital Crown to return to the actual watch face. Through the face editor select a compatible face with circular and rectangular slots (for example Modular), select the installed Timbre complications, and return to the system face. Verify the real streak and set content. Save the actual simulator screen, or run `xcrun simctl io <watch-udid> screenshot --type=png --mask=black <face.png>` while that face is frontmost, after confirming these public options in installed help. Use the job's honestly labeled native JPEG fallback only when those options are absent. Record source SHA, Watch/runtime identifiers, system language, native dimensions, opacity/alpha-channel status, screenshot hash, face name, complication families and visual sign-off. Repeat for any localized face images intended for upload; process language arguments for the app do not prove the system face's language. If the current runtime cannot configure the development widgets, leave this item open and use a paired device once available.

Apple documents manual face editing after running a development app in Simulator. That is a supported genuine path, but this Windows session cannot operate the hosted Mac's face editor, and no public documented simctl face-configuration operation was found. [Apple complication sample instructions](https://developer.apple.com/documentation/clockkit/displaying-essential-information-on-a-watch-face), [Simulator screenshots](https://developer.apple.com/library/archive/documentation/IDEs/Conceptual/iOS_Simulator_Guide/InteractingwiththeiOSSimulator/InteractingwiththeiOSSimulator.html).

The public `CLKWatchFaceLibrary` API imports an already-created `.watchface` file in response to a user action. Apple states that complications in imported faces need a valid App Store ID; development-build IDs are not recognized. It therefore cannot close an unattended pre-account development capture requirement by importing a fabricated face configuration. [Face sharing](https://developer.apple.com/documentation/clockkit/sharing-an-apple-watch-face), [addWatchFace](https://developer.apple.com/documentation/clockkit/clkwatchfacelibrary/addwatchface(at:completionhandler:)). No watch-face file, composited face, widget preview, signing setup or account dependency was introduced by this capture job.
