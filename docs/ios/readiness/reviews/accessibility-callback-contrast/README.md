# Bounded callback contrast investigation

The exact native audit for app source `0b89f9ba4913bf5910302c059b30ce1aa1a59cc4`, run `40573532661`, **failed**. The retained callbacks identified visible Settings “Note names” and yearly offer “SAVE 58%” text. Their actual foreground/background core colors measured 16.78:1 and 12.89:1 in the callback screenshot bounds. The attached crops retain original pixel values; the JSON binds the full original screenshots and reported point/pixel bounds. These measurements do not certify another frame or suppress the audit by themselves.

The proposed test-only `AuditContrastPixelProof` accepts only these two exact screen/identifier/label combinations and only contrast callbacks on static text. Every callback must independently prove visible glyph-like strokes and backing in its current screenshot, at least 4.5:1 conservative contrast, sufficient expected paint coverage, spatial distribution and connected ink components. A changed label, wrong frame, unknown identity, absent ink, solid patch, low contrast or unsupported image remains a failure. Point-to-pixel mapping uses the pre-audit app viewport, rejects rotated/mismatched viewports and does not rely on UIImage scale metadata. Proof screenshots are retained. This is not an unconditional exception or OCR certification.

Four native regression tests exercise positive and negative controls. Their execution is pending on the new candidate. The Songs contrast findings, Dynamic Type timeout, other audit types and opaque callback behavior remain enforced. No production color, price, accessibility label text or readiness flag changes are made by this investigation. Settings titles receive stable identifiers; data handling is unchanged.
