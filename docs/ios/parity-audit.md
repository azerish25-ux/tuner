# Android → Swift parity audit

Audit basis: current `reference/android` implementation, rather than aspirational briefs. This is a source inspection, not a claim of simulator or hardware verification. Core tests were reported passing on macOS at a79e0a5; the earlier application compile reached code compilation but failed asset validation, subsequently addressed by the parent. Later app/StoreKit tests remain pending until their actual workflow results are inspected.

## Material findings requiring closure

1. **Practice history was missing shipped measured analytics.** Android `feature/progress/.../HistoryStateHolder.kt` and `ProgressScreen.kt` show seven calendar days of practice duration, session duration/stable fraction, recent versus earlier fortnight measured tuning accuracy, and voice challenge best score/attempt count. The earlier Swift `PracticeRecord` lacked duration; `HistoryView` showed counts rather than these charts/comparisons. `PracticeAnalytics.swift` and `PracticeAnalyticsTests.swift` now implement these calculation contracts; parent is adding duration capture and another agent is integrating the UI. Those edits and CI still require verification. Missing historical duration must stay unknown, not become zero.
2. **History retention must not silently discard evidence.** Android `SessionRepository.record` calls DAO insert; DAO `LIMIT` clauses are read limits only. Session deletion is explicit `deleteAll`. Voice progress is independently accumulated in `progress_records` using maximum score and incremented attempts. Swift's earlier 500-record trim would silently erase all-time progress when analytics derives it from records. Parent notified to remove destructive trimming and cap validation; retain all evidence, optionally limit visible recent rows.
3. **Studio tuning desk lacks the shipped preset list and note summaries.** Android `app/.../StudioRoute.kt::StudioTuningDesk` displays current tuning note labels and a selectable complete list of current-instrument presets. Initial Swift `StudioView` only showed current tuning and Open tuner. Parent notified. A tuning selector elsewhere does not establish Studio parity.
4. **Bench must retain physical/action cues.** Android `InstrumentStage.kt::TargetNote` uses `TargetLabelFormatter.splitCue`; original course labels include blow/draw, valve, hand/string and other playing cues. Swift's initial `targetName` and peg strip displayed MIDI names alone, losing these annotations. Parent notified; preserve original cue alongside the selected notation/transposition rather than replacing either.
5. **Privacy copy conflicts with newly integrated ads.** Initial Swift Settings About said there was no advertising SDK while `AdvertisingService` imports AdMob and UMP. This must describe actual SDK/consent behavior and retain the source privacy URL before delivery. Parent notified.
6. **Full localization remains unproven.** Forty-nine locale tables were imported and imperative strings resolve selected-language bundles. Numerous Swift-only literals, voice instructions/explanations and commerce error messages are English. Native Locale alone does not translate literal strings without matching localized keys. Imported Android-specific Google Play/Android settings strings must not be displayed on iOS. Parent notified; visual/language QA still needed.
7. **Voice guidance differs.** Shipped Android `SingingScreen.kt::VoiceExerciseControls` supplies signal-dependent directional coaching (higher/lower/little higher/little lower), input meter and continuous hold progress. Initial Swift VoiceView shows live cents/Hz and generic clear/settling state, but no input meter or directional guidance. Parent notified; current domain exercise coverage does not prove these UI behaviors.
